# Segundo Cérebro de ServiceNow com NotebookLM

## Sobre o projeto

Este projeto foi desenvolvido como parte de um desafio da DIO.

Escolhi estudar **ServiceNow** usando o NotebookLM como apoio. A ideia foi criar um caderno de estudos e usar a inteligência artificial como uma espécie de tutor, ajudando a organizar os conteúdos e explicar os assuntos de forma mais simples.

O foco foi aprender ServiceNow desde o início e ir avançando aos poucos para assuntos mais técnicos.

---

## Objetivo

O objetivo do projeto foi criar um material de estudo para iniciantes em ServiceNow.

Os principais assuntos estudados foram:

- o que é ServiceNow;
- aplicações e módulos;
- tabelas, registros e campos;
- ITSM;
- Incident Management;
- Problem Management;
- Flow Designer;
- administração da plataforma;
- conceitos básicos de desenvolvimento.

## Dificuldades e aprendizados

Uma das coisas que percebi durante o projeto foi que perguntas muito abertas geravam respostas muito grandes.

Por exemplo:

> Explique ServiceNow.

Quando comecei a fazer perguntas mais específicas, as respostas ficaram melhores.

Exemplo:

> Explique ServiceNow para uma pessoa iniciante e dê exemplos simples.

Também percebi que pedir exemplos e comparações ajudou bastante no aprendizado.

Outro ponto importante foi pedir para o NotebookLM usar somente as fontes adicionadas no caderno.

# Miniguia de ServiceNow

## O que é ServiceNow?

ServiceNow é uma plataforma em nuvem usada para organizar e automatizar processos dentro das empresas.

Ela é muito conhecida pelo uso em TI, mas também pode ser usada em outras áreas.

---

## Aplicações e módulos

As aplicações organizam as funcionalidades da plataforma.

Dentro delas existem módulos que permitem acessar diferentes recursos.

---

## Tabelas

Os dados do ServiceNow ficam armazenados em tabelas.

Por exemplo, os incidentes ficam armazenados em uma tabela de incidentes.

---

## Registros

Cada item dentro de uma tabela é um registro.

Por exemplo, cada incidente criado é um registro.

---

## Campos

Os campos guardam informações de cada registro.

Exemplos:

- descrição;
- prioridade;
- status;
- usuário.

---

## ITSM

ITSM significa gerenciamento de serviços de tecnologia.

Alguns processos importantes são:

- Incident Management;
- Problem Management;
- Change Management;
- Request Management.

---

## Incident Management

É usado quando acontece uma falha ou interrupção em um serviço.

O objetivo é fazer o serviço voltar a funcionar o mais rápido possível.

---

## Problem Management

Busca entender a causa de um ou mais incidentes.

Enquanto o Incident Management resolve o problema imediato, o Problem Management tenta descobrir a causa.

---

## Flow Designer

É uma ferramenta usada para criar automações.

Exemplo:

Um incidente é criado  
→ o sistema verifica a prioridade  
→ envia uma notificação.

---

## Administração

A administração da plataforma pode envolver:

- usuários;
- grupos;
- permissões;
- tabelas;
- campos;
- configurações.

---

## Desenvolvimento

O ServiceNow também permite criar e personalizar aplicações.

Isso pode envolver:

- criação de tabelas;
- formulários;
- automações;
- scripts;
- regras de negócio.

---

## Glossário

| Termo | Significado |
|---|---|
| Application | Conjunto de funcionalidades |
| Module | Opção dentro de uma aplicação |
| Table | Local onde os dados ficam armazenados |
| Record | Registro dentro de uma tabela |
| Field | Informação de um registro |
| Incident | Interrupção de um serviço |
| Problem | Causa de um ou mais incidentes |
| Flow | Automação |
| Trigger | Evento que inicia um fluxo |
| Instance | Ambiente do ServiceNow |
| Role | Permissão de usuário |
